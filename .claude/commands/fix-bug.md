# Bug 修复流程

用户会描述一个 bug。严格按以下步骤执行，不跳步。

## 1. 理解
- 用一句话复述用户描述的问题
- 说明你认为的**根因**（不是症状）
- 列出你打算改哪些文件
- 如果涉及高危文件（App.tsx / useRecordingFlow.ts / useSlides.ts），明确告知用户

## 2. 确认
- **等用户确认**上述理解正确后再动手
- 用户说"对"或"去吧"才算确认

## 3. 存档
- 执行：`git add -A && git commit -m "checkpoint: pre-fix [bug简述]"` 保存当前状态
- 如果工作区干净，跳过此步

## 4. 修复
- 只改与这个 bug 直接相关的代码
- **不要**顺手重构、改命名、调格式、提取函数
- **不要**改用户没提到的功能
- 改之前先 `git show 56515ab:path/to/file` 看原始实现

## 5. 验证
- 说明如何手动验证这个修复
- 如果改了 UI，描述预期视觉变化
- 运行 `npm run test:regression` 确认没有破坏已有功能
- 报告测试结果（全通过 / 哪些失败了）

## 6. 判定
- 回归测试全通过 → 进入步骤 7
- 回归测试有失败 → **立刻回退** `git checkout .`，回到步骤 1 换思路
- 连续 3 轮到这一步都有失败 → **停下来告知用户**，不要继续试

## 7. 提交
- `git add -A && git commit -m "fix: [具体修复内容]"`
- commit message 写清改了什么 + 为什么
